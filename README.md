# 문도 피구 (Dr. Mundo Dodgeball)

Phaser 3 기반 2.5D 문도 피구. 브라우저 안에서 도는 봇전과, 초대 링크로 들어오는 친구와의 온라인 1대1을 지원한다.

## 실행

```bash
npm install      # 최초 1회 (스프라이트 굽기용 의존성 + 게임 서버의 ws)
npm start        # http://localhost:5173
npm run server   # 친구와 대결용 게임 서버 ws://localhost:3000/ws
```

localhost 에서 열면 게임은 `ws://localhost:3000/ws` 에 붙는다. 배포 페이지는 `wss://3.37.101.179/ws` 를 쓰며, `?server=ws://...` 쿼리로 다른 서버를 지정할 수 있다 (초대 링크에도 유지됨). 로컬에서 두 창을 띄워 직접 대결해 볼 수 있다.

## 조작
우클릭(또는 좌클릭) 이동 · Q 장착 무기 투척 · D 점멸 · F 유체화 · S 정지 · M 음소거

## 상점 · 콜로세움 MVP

메인 화면 모드 카드 바로 위 **상점**에서 경기장 이미지를 확인하고, 코인으로 구매한 뒤 적용한다. 기본 **바위 협곡**은 무료이며, **문도 콜로세움**은 1,500코인이다. 코인은 처음 100에서 시작해 승리 100·패배 30을 받는다. 콜로세움은 모래 바닥, 석조 관중석과 관객, 아치, 붉은 깃발, 화로로 구성된다.

- 첫 방문에 100코인을 지급한다. 정상 종료한 봇전·온라인 대전의 승리는 100코인, 패배는 30코인을 지급하며 상점에서 잔액을 확인할 수 있다. 동시 사망 재경기와 상대 연결 종료에는 별도 보상이 없다.
- 구매와 적용은 별도 버튼 단계다. 이미 보유한 맵에는 중복 비용이 들지 않으며 기본 맵으로 언제든 돌아갈 수 있다.
- **투척 무기**에서 **클래식 축구공**을 300코인으로 구매하고 별도로 장착한다. 기본 무기는 무료 식칼이다. 축구공은 내 캐릭터의 손에 든 무기·8방향 전체 동작·날아가는 투척물·Q 아이콘과 이름을 바꾼다. 속도·피해량·충돌 범위·쿨다운은 같다. 봇의 무기는 기본 식칼로 표시한다. 온라인에서는 방에 들어갈 때 장착한 무기를 서버에 알려 상대 화면에도 같은 무기와 투척물이 보인다.
- 무기 보유 내역(`ownedWeapons`)과 장착(`equippedWeapon`)은 기존 `mundo-shop-v1`에 함께 저장한다. 이전 저장에는 무료 식칼을 자동으로 추가하며 기존 코인·맵·보상 내역을 보존한다. `npm run check:soccer`로 구매·저장 호환·실제 투척/명중·온라인 양쪽 진영·모바일 상점·식칼 복귀를 검사한다.
- **스킨**에서 **호날두 문도**를 777코인으로 구매하고 별도로 장착한다. 기본 문도의 조끼를 맨유 느낌의 빨간색으로 바꾸고 흰색 7번, 올백 머리, 호날두 사진을 인쇄한 가면과 끈을 더한다. 체형·팔·짧은 다리·맨발·동작은 기본 문도와 같다. 기본 문도는 무료이며, 무기는 스킨과 독립적으로 선택한다. 대기실과 실제 대전의 내 캐릭터에 적용되며 온라인에서는 상대 화면에도 보인다. 상대 외형은 경기 시작(재대결 포함)과 재접속 때마다 서버가 보내는 값으로 다시 정한다. 이동·공격 성능은 동일하다.
- 스킨 보유 내역(`ownedSkins`)과 장착(`equippedSkin`)도 기존 저장에 함께 보관한다. 이전 저장에 기본 스킨을 자동 추가하며 기존 구매·코인·보상을 유지한다. `npm run bake:ronaldo`로 식칼·축구공 조합의 8방향 동작을 생성한다. `npm run check:skins`로 저장 호환·구매·장착·재접속·두 무기 조합·실제 명중·온라인 양쪽 진영·모바일 화면·기본 스킨 복귀를 검사한다. 원화와 생성 기록은 `assets/cartoon/ronaldo/`에 있다.
- 맵은 외형만 바꾼다. 이동·식칼·승패 판정은 기존 규칙을 공유하며, 콜로세움의 축소 영역은 모래 위 붉은 경계와 음영으로 표시한다. 온라인에서는 각자의 화면에 선택한 외형을 적용한다.
- 대전 화면의 배율과 중심은 모든 맵에서 같다. `npm run check:arena-scale`로 PC·모바일 가로·세로 화면에서 두 맵의 경기장·캐릭터 크기와 위치가 같은지 검사한다.
- 맵 이미지는 가로·세로를 같은 배율로 확대해 원본 비율을 유지한다. 콜로세움의 실제 이동 경계는 모래 위 갈색 타원으로 별도 표시한다. 그림 속 돌 테두리까지 이동할 수 있다는 뜻은 아니다.
- 레티나 화면에서도 픽셀아트 모드를 명시적으로 끄고 선형 보간을 사용한다. Phaser는 `scale.zoom !== 1`이면 기본적으로 픽셀아트 모드를 켜므로 `render.pixelArt: false`를 유지해야 한다. `npm run check:arena-quality`로 화면 배율 1·2·3에서 실제 GPU 필터와 캔버스 확대 방식을 검사한다.
- 코인·구매 내역·선택은 `mundo-shop-v1` 브라우저 저장소에 남는다. 저장을 사용할 수 없으면 이번 방문 동안 유지하며 상점에 안내한다. 로그인·서버 인벤토리·현금 결제가 없는 로컬 MVP다.

상점은 `src/shop.js`, 저장·구매·보상은 `src/shop-state.js`에서 관리한다. 현재 콜로세움은 사용자가 선택해 첨부한 `assets/cartoon/colosseum-selected-v1.png`(1283×1226)를 원본 그대로 사용하며, 투명 배경과 빈 관중석을 유지한다. 같은 이름의 JSON이 모래 바닥의 중심과 타원 반경을 기록하며, 바닥이 전체 이동 범위를 포함하는 균일 배율로 표시한다. 출처와 이전 생성 기록은 `assets/cartoon/COLOSSEUM-GENERATION.md`에 있다. `npm run bake:colosseum`은 이전 도형 기반 레이아웃 참고 이미지(`colosseum.png`)만 재생성하며 현재 맵을 덮어쓰지 않는다. `npm run check:shop`으로 구매·적용·저장·보상·모바일 레이아웃을 검사한다.

축구공은 내장 이미지 생성 도구로 캐릭터 원화를 참고해 만든 투명 PNG `assets/cartoon/soccer-ball-v2.png`를 상점과 투척물에 함께 사용한다. 굵은 먹선, 크림색 패널과 단순한 보라 회색 그림자로 캐릭터의 카툰 그림체에 맞췄다. 손에 든 모습은 `assets/cartoon/soccer-parts-v4.png`의 두 번째 열을 사용한다. 사용자가 선택한 원본의 팔과 주먹 모양을 유지하고 공을 손 뒤로 넣어 약 절반이 가려지도록 조정했다. 식칼과 갈색 손잡이는 없앴다. 원본 아틀라스의 어깨 좌표로 등록해 공이 추가되어도 팔의 크기와 위치가 달라지지 않는다. 생성 프롬프트는 `assets/cartoon/SOCCER-GENERATION.md`에 기록했다. `npm run bake:soccer`는 기존 몸체와 전용 팔로 축구공 전용 WebP 아틀라스를 `assets/cartoon/soccer/`에 굽는다. 공을 놓은 뒤에는 기존 빈손 팔로 전환하고, 기존 식칼 아틀라스는 덮어쓰지 않는다.

축구공 Q 스킬에는 별도의 `assets/cartoon/soccer-throw-icon-v1.png`를 사용한다. 기존 식칼 투척 아이콘을 바탕으로 문도가 축구공을 던지는 장면과 초록색 궤적을 그려, 점멸·식칼과 같은 스킬 아이콘 그림체를 유지한다. 프레임과 Q 표시는 기존 화면에서 그린다.

식칼 Q 스킬은 문도가 식칼을 던지는 전용 그림 `assets/cartoon/cleaver-throw-icon-v1.png`를 사용한다. 상점의 단독 무기 그림 `cleaver-icon.png`와 파일을 분리해 상품 이미지 변경이 스킬 아이콘에 영향을 주지 않게 한다.

## 배경음악
Scott Buckley의 **Path Through The Mountains**를 사용한다 ([원곡](https://www.scottbuckley.com.au/library/path-through-the-mountains/), [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)). 게임 화면 우측 하단에 작게 출처를 표시한다. 봇전 또는 온라인 경기에 들어가면 낮은 볼륨으로 반복 재생하며 결과 화면까지 이어진다. 메인 메뉴와 대기실에서는 음악과 출처를 표시하지 않고, 메뉴로 돌아가면 음악을 멈추고 재생 위치를 초기화한다. M 키 또는 메인 화면 설정(톱니바퀴)의 **소리** 스위치로 효과음과 함께 음소거한다. 소리 끔은 `mundo-muted-v1` 로컬 저장소 키에 남아 다음 방문에도 유지된다(저장이 막혀 있으면 이번 방문만). 탭을 숨기면 음악을 일시 정지했다가 돌아오면 이어서 재생한다. 음원과 사용 조건은 `assets/audio/`에 있다.

## 분석

선택을 저장하지 않은 첫 메인 화면에서는 동의 팝업을 자동으로 표시한다. 동의·거부를 선택하면 팝업이 닫히며 이후 방문에서는 다시 표시하지 않는다. Escape로 선택 없이 닫으면 해당 방문에서는 수집하지 않고, 다음 방문에 다시 안내한다. 메인 화면 우측 상단의 톱니바퀴 설정에서 **플레이 통계 전송** 스위치로 바로 동의·철회할 수 있다(아직 고르지 않았으면 꺼진 상태로 보임).

메인 화면에서 선택적 개인정보 수집·이용에 동의한 경우에만 `src/analytics.js`에서 PostHog 미국 리전으로 사용 이벤트를 전송한다. 동의 전과 거부 상태에서는 SDK를 로드하지 않고 이벤트를 보관하거나 전송하지 않는다. 선택은 `mundo-analytics-consent-v1` 로컬 저장소 키에 저장하며, 메인 화면의 ‘동의 설정’에서 변경·철회할 수 있다. 철회하면 SDK 수집을 중단하고 분석용 저장 데이터를 지운다. 이미 전송된 데이터의 삭제는 별도 처리다. 저장소가 차단되어 있으면 현재 방문에서만 선택을 유지한다. 브라우저용 Project API key를 사용하며, 로그인 식별·자동 클릭 수집·세션 녹화는 사용하지 않는다. localhost, 루프백 주소, `/tools/`에서는 SDK 로드와 전송을 끈다.

- `$pageview`: 동의한 상태의 페이지 방문 (동의 전 방문은 기록하지 않음)
- `game_started`: 실제 게임 시작. `match_id`, `difficulty` (쌍둥이는 `twins`), `source` (`menu` 또는 `replay`)
- `game_finished`: 승패 확정. 같은 판 속성과 `result` (`win` 또는 `loss`), `duration_seconds` (실제 게임 진행 시간, 결과 대기 제외)
  - 플레이어의 `throws` (실제 발사된 식칼 수), `hits` (상대에게 명중한 식칼 수), `accuracy` (`hits / throws`, 0~1 비율)를 판 전체로 요약한다. 투척이 없으면 명중률은 0이다. 발사 전에 취소된 투척은 제외하며, 무승부 재경기는 합산하고 새 게임·재도전에서는 초기화한다.
  - 적도 같은 기준으로 `enemy_throws`, `enemy_hits`, `enemy_accuracy`를 기록한다. 쌍둥이 모드는 두 봇의 횟수를 합산하고, 명중률은 합산 명중 수 / 합산 투척 수로 계산한다.
- `replay_clicked`, `menu_returned`: 결과 화면에서 재도전 또는 난이도 선택. 직전 판 속성 포함
- 빠른 대전: `quick_queue_started`, `quick_matched`(`room`, `opponent`: `human`/`bot`, `wait_ms`: 큐에 선 뒤 매칭까지), `quick_cancelled`(`wait_ms`), `quick_requeue_clicked`(결과 화면의 새 상대 찾기, 직전 판 속성). 대인전의 `game_started` / `game_finished`에는 `match_type`(`quick` / `invite`)과 `opponent`(`human` / `bot`)를 붙이고, 빠른 대전 첫 판의 `source`는 `quick`이다.
- 친구와 대결: `online_room_created`(`room`), `online_room_joined`(`room`, `slot`), `online_invite_shared`, `online_rematch_clicked`, `online_opponent_left`. 대인전의 `game_started` / `game_finished`는 `difficulty: online`, `mode: online`, `room`, `source` (`online` / `rematch` / `resume`)를 갖는다. 적 수치(`enemy_*`)는 상대 사람의 기록이다.

공유 성장 지표:

- 승리 결과에서는 `자랑하기`, 패배 결과에서는 `공유하기` 버튼을 표시한다. 공유 메시지에는 난이도와 결과를 표시하고, 승패 모두 `날아오는 식칼을 피하고, 상대 문도를 쓰러뜨리는 피구 게임` 설명을 사용한다.
- `share/`의 난이도·승패별 정적 페이지가 메신저용 OG/Twitter 문구와 이미지를 제공하고, 방문자는 추적 쿼리를 유지한 채 게임으로 이동한다. 문구 또는 디자인 수정 후 `node tools/render-share-preview.mjs`로 페이지와 이미지를 함께 다시 생성한다.

- 친구 초대로 진행한 1대1에서 이긴 쪽에는 `굴욕 선사하기` 버튼을 표시한다(패배·봇전·빠른 대전에는 없음). 모달에서 상대 이름(최대 12자, 비워도 됨)을 넣으면 `{이름}? 발로 해도 이긴다 ㅋ`(비우면 `넌 발로 해도 이긴다 ㅋ`)와 `share/humiliate.html` 링크를 함께 복사한다. 링크 미리보기는 고정 짤(`assets/cartoon/share-preview-humiliate.png`)과 제목 `넌 발로해도 이긴다 ㅋ`이고, 이름은 복사 문구에만 들어간다.

- `share_clicked`: 공유 버튼 클릭마다 새 무작위 UUID `share_id` 생성. `match_id`, `difficulty`, `result` 포함
- `share_completed`: 네이티브 공유 API 성공 (`method: native`) 또는 클립보드 복사 성공 (`method: clipboard`). 실제 친구에게 전달·열람되었다는 뜻은 아니다.
- `share_cancelled`: 네이티브 공유창 취소
- `share_failed`: 자동 복사 실패. 복사 완료로 집계하지 않는다.
- `humiliate_clicked`: 굴욕 모달 열기 (`mode: online`, `room`). 복사 결과는 `share_completed` / `share_failed`에 `kind: humiliate`, `share_id`, `room`을 붙여 보내며, 입력한 이름은 보내지 않는다. 링크는 `utm_medium=humiliate`.
- 공유 URL에 `share_id`, `utm_source=friend`, `utm_medium=share`를 붙인다. 기존 쿼리·해시는 전달하지 않는다. 사용자 ID나 이메일을 링크에 넣지 않는다.
- `invite_opened`: 유효한 UUID v4 `share_id`가 있는 페이지 방문. 새로고침도 이벤트가 발생하므로 유입 성과는 고유 사용자로 집계한다. 자기 링크 방문이나 전달된 링크의 재공유도 포함될 수 있어 실제 친구 수와 같지는 않다.
- `game_started`, `game_finished`에는 `entry_source` (`share` / `direct`)를 추가하고 공유 유입이면 `referral_share_id`도 붙인다. 이 귀속은 현재 페이지와 그 안의 재도전 동안 유지되며, 추적 파라미터 없는 새 방문에는 이어지지 않는다. `source` (`menu` / `replay`)는 게임 시작 방식으로 별도 유지한다.

공유 의향은 게임 완료 고유 사용자 중 공유 클릭 고유 사용자 비율로 본다. 친구 쪽 퍼널은 `invite_opened` → `game_started` → `game_finished`로 구성하고, 유입의 `share_id`와 게임의 `referral_share_id`가 같도록 연결한다. 공유자는 다른 사용자이므로 `share_clicked`를 같은 사용자 퍼널의 첫 단계에 넣지 않는다. 공유별 유입 성과는 `share_id`로 별도 집계한다. 링크를 받은 전체 인원은 알 수 없으므로 완료율 분모는 공유 링크 방문 고유 사용자로 둔다.

배포 후 PostHog의 Activity에서 방문 → 시작 → 종료 → 재도전 이벤트를 확인한다. 방문 → `game_started` 퍼널, 난이도별 승률, 플레이 시간, 재도전율을 초기 지표로 사용한다. 페이지를 닫아 중단한 판에는 `game_finished`가 없으므로 종료율 해석 시 구분한다.

## 프로필 · 룬

메인 화면 모드 카드 바로 위(상점 왼쪽) **룬 설정**에서 숙련도(레벨)·경험치와 룬을 확인하고 고른다. 화면은 `src/profile.js`·`profile.css`, 저장은 `src/profile-state.js`에서 관리한다.

- 경험치: 정상 종료한 봇전·온라인 대전의 승리 +100, 패배 +40. 같은 판은 한 번만 받는다(코인과 같은 `match_id` 기준). 결과 화면 위쪽에 받은 경험치와 현재 레벨을 짧게 보여 준다.
- 레벨: 레벨 n에서 다음 레벨까지 `100 + 50 × (n − 1)` 경험치가 필요하다. 표시용이며 해금 요소는 없다.
- 룬: 투척·이동·유틸 세 칸에서 하나씩 고른다. 기본값은 모두 **기본**(효과 없음)이며, 기본 룬끼리는 기존 수치와 완전히 같다.

| 칸 | 룬 | 장점 | 단점 |
|---|---|---|---|
| 투척 | 강속구 | 공 속도 +25% | 주는 피해 −20% |
| 투척 | 묵직한 한 방 | 주는 피해 +25% | 공 속도 −20% |
| 투척 | 서리 칼날 | 둔화 2→3초 | 주는 피해 −15% |
| 이동 | 날쌘 발 | 이동 속도 +12% | 받는 피해 +15% |
| 이동 | 강철 피부 | 받는 피해 −15% | 이동 속도 −10% |
| 이동 | 유령 걸음 | 유체화 지속 5→7초 | 유체화 쿨다운 25→32초 |
| 유틸 | 연사 | 투척 쿨다운 4→3초 | 투척 체력 소모 50→80 |
| 유틸 | 재생 | 체력 재생 7→12/초 | 점멸 쿨다운 15→20초 |
| 유틸 | 흡혈 | 명중 시 체력 +30 회복 | 체력 재생 7→4/초 |

- 수치는 `src/rules.js`의 `RUNES`에서 조정한다. `runeMods`가 룬을 배율·값으로 풀고, `src/sim.js`가 이동·식칼 속도·피해·둔화·쿨다운·유체화·재생·흡혈에 반영한다. 사거리는 같다.
- 봇전에서는 내 캐릭터에만 적용하고 봇은 기본 룬이다. 봇은 날아오는 공의 실제 속도로 피하고 조준한다.
- 온라인에서는 방에 들어갈 때 외형과 함께 룬을 서버에 보내고(`cleanLook`가 모르는 값을 기본 룬으로 정리), 서버가 그 룬으로 판정한다. 공 속도는 스냅샷·투척 이벤트에 실려 양쪽 화면이 같은 속도로 그린다. 친구 대기실에는 양쪽의 룬을 표시한다. 경기 중 재접속으로 바꾼 룬은 다음 경기부터 적용된다. 고스트 기록에는 그 사람의 룬도 함께 남기고(성향을 그 룬으로 쟀으므로), 빠른 대전의 문도봇은 고른 기록의 룬을 그대로 쓴다. 기본 성향과 룬이 없는 예전 기록은 기본 룬이다.
- 경험치·룬은 `mundo-profile-v1` 브라우저 저장소에 남는다. 잘못된 값은 0 경험치·기본 룬으로 되돌리며, 저장을 쓸 수 없으면 이번 방문 동안만 유지한다.
- `npm run check:profile`로 창 열기·룬 선택·저장·복구·봇전 반영·경험치 지급과 중복 방지·PC/모바일 배치를 검사한다. `npm run check:sim`은 룬별 공 속도·피해·쿨다운·재생 계산을, `npm run check:online`은 서로 다른 룬의 서버 판정과 대기실 표시를 검사한다.

## 승부 규칙
상단 양쪽 초상화 옆에 현재 체력을 표시한다. 시간 제한 없이 상대를 쓰러뜨리면 승리하는 단판 승부다. 동시에 쓰러지면 재경기한다.
봇전에서는 라운드 시작 즉시 60초 동안 플레이어 쪽 왼쪽 반원의 반지름이 처음의 70%까지 서서히 줄어든다. 플레이어의 이동 범위만 함께 줄어들며, 경계에 닿으면 안쪽으로 밀려난다. 오른쪽 봇 진영은 경계선과 이동 범위 모두 처음 크기를 유지한다. 재경기와 메뉴 복귀 시 원 크기가 초기화된다.

## 빠른 대전 (문도봇 고스트)
메뉴의 **빠른 대전**은 방 코드 없이 상대를 찾는다. 큐는 하나뿐이고, 먼저 기다리던 사람이 있으면 준비 단계 없이 바로 카운트다운한다. 15초 안에 아무도 오지 않으면 서버가 **문도봇**을 상대로 붙인다. 문도봇은 숨기지 않는다: 이름표가 `문도봇 · BOT`이고, 대기 화면에서 시간이 지나면 문도봇과 붙는다고 알린다. 빠른 대전 결과에는 사람·문도봇 상대 모두 굴욕 선사하기와 재대결이 없고 `새 상대 찾기`와 `뒤로가기`만 있다. `새 상대 찾기`는 방을 나와 다시 큐에 선다. 그 밖의 규칙(경기장 고정, 단판, 연결 끊김)은 친구와 대결과 같다.

- **고스트**: 문도봇은 실제 대인전 유저의 성향을 본뜬다. 사람끼리 끝난 경기(빠른 대전과 친구 초대 모두, 15초 이상이고 4번 이상 던진 사람)마다 서버가 명중률·위협 식칼 회피율·식칼이 준비된 뒤 던지기까지 걸린 시간·분당 점멸과 유체화 횟수·중앙선에서 평균 거리를 재어(`server/ghost-profile.mjs`), `src/ghost.js`의 `profileToDiff`로 봇 수치(`src/bot.js`와 같은 모양)로 바꾼다. 문도봇 경기는 기록하지 않는다.
- **기본 성향**: 기록이 없을 때는 기본 성향만 쓴다. 어려움부터 페이커, 페이커보다 어려운 단계까지 12가지에, 가끔 나오는 쉬움·보통 3가지를 더한 15가지다(쉬움·보통이 나올 확률 20%). 기록이 있으면 70%는 실제 고스트, 30%는 기본 성향에서 고른다. 둘 다 똑같이 `문도봇`으로 보인다.
- **저장**: 이름·IP·방 코드 없이 숫자만 `ghosts.json` 하나에 최근 300개까지 둔다. 배포 서버는 systemd `StateDirectory`(`/var/lib/mundo-pigu`), 로컬은 `server/.data/`(git 제외). 서버 `/health`에 `quickWaiting`과 `ghosts` 개수가 나온다.
- **보정**: `npm run calibrate:ghost`는 화면 없이 단계별 봇을 보통 봇과 붙여 같은 방법으로 재고, `ANCHORS` 표와 되돌림 확인(측정치 → 봇 수치가 원래 단계로 돌아오는지)을 출력한다. 봇 수치를 바꾸면 다시 돌려 `src/ghost.js`에 반영한다.
- **검사**: `npm run check:quick` (콜로세움에서 사람 둘 즉시 매칭과 고스트 기록, 혼자일 때 문도봇 매칭·이동·투척·표시, 봇 결과에 재대결 없음, 새 상대 찾기, 대기 취소, 봇 경기 미기록). `QUICK_MAP=classic npm run check:quick`으로 기본 맵도 검사한다. 검사용 서버는 `MUNDO_TEST=1`에서 `QUICK_WAIT_MS`, `GHOST_MIN_THROWS`, `GHOST_MIN_SECONDS`로 기다림과 기록 기준을 줄인다.

## 친구와 대결 (온라인 1대1)
로그인 없이 초대 링크로 1대1을 한다. 메뉴의 **친구와 대결**을 누르면 방이 만들어지고, 대기실의 초대 링크(`?room=코드`)를 받은 친구는 메뉴를 거치지 않고 같은 방 대기실로 들어온다. 두 사람이 모두 **준비**를 누르면 3초 카운트다운 뒤 시작한다. 방장은 왼쪽, 친구는 오른쪽 진영에 서며 화면은 뒤집지 않는다. 내 문도만 초록 링·체력바로 표시하고, 식칼을 맞히면 양쪽 모두 따봉을 띄운다.

- **판정**: 서버가 `src/sim.js`로 60Hz 계산하고 이동·투척·점멸·유체화·체력·충돌·승패를 최종 판정한다. 30Hz 스냅샷과 즉시 이벤트(투척·적중·사망 등)를 보낸다.
- **지연 보정**: 내 문도는 클릭·스킬에 바로 반응(로컬 예측)하고, 스냅샷이 오면 서버 위치를 내 이동 목표 쪽으로 왕복 시간만큼 진행시켜 비교해 0.35유닛 이상 어긋날 때만 초당 최대 3유닛씩 맞춘다(1.5유닛 이상은 즉시). 체력·사망·적중은 서버 값을 따른다. 상대 문도는 스냅샷 도착 시각 기준 100ms 이전 시점을 보간해 그린다. 식칼은 서버 목록 기준으로 생성·제거하고 경과 시간만큼 앞으로 그린다.
- **대인전 규칙**: 경기장이 줄어들지 않고 양쪽 경계가 같다. 그 밖의 수치·단판 승부·동시 사망 재경기는 봇전과 같다.
- **연결 끊김**: 경기 중 한쪽이 끊기면 경기를 멈추고 남은 사람에게 15초 카운트를 보여준다. 끊긴 쪽이 새로고침하거나 자동 재연결(같은 탭의 `sessionStorage` 토큰)로 15초 안에 돌아오면 이어서 하고, 아니면 "상대가 나갔어요" 결과로 끝낸다. 결과 화면이나 대기실에서 나가도 상대에게 알린다.
- **재대결**: 결과 화면의 **재대결**을 한쪽이 누르면 상대에게 "친구가 재대결을 원해요"를 보여주고, 둘 다 누르면 같은 방에서 카운트다운부터 다시 시작한다.
- 방은 둘 다 나가거나 10분 동안 아무 메시지가 없으면 지운다. 방 코드는 헷갈리는 0/O, 1/I를 뺀 6자리다.

### 서버 배포 (Lightsail)
nginx가 `https://3.37.101.179/ws`를 `127.0.0.1:3000/ws`로 WebSocket 업그레이드해 넘기고, 게임 서버는 systemd(`server/mundo-pigu.service`, `DynamicUser`, 자동 재시작)로 실행한다. 3000번 포트는 외부에 열지 않는다. 배포는 다음 한 줄로 소스 복사 → `npm ci --omit=dev` → 서비스 재시작 → `/health` 확인까지 한다.

```bash
SSH_TARGET=ubuntu@3.37.101.179 SSH_KEY=~/.ssh/<lightsail-key>.pem server/deploy.sh
```

허용 Origin은 배포 서버(`NODE_ENV=production`)에서 `https://trashesss.github.io`뿐이고, localhost 페이지는 로컬에서 띄운 개발 서버(`npm run server`)에서만 허용한다. 다른 도메인은 `EXTRA_ORIGINS=https://a.example,https://b.example` 환경 변수로 추가한다.

## 구조
- Q 투척은 참고 영상처럼 식칼을 머리 위로 들어 올린 뒤 상체와 함께 앞으로 휘두르고, 발을 디딘 채 자세를 회복한다. 30프레임을 60fps로 재생하며 `src/throw-motion.js`에서 투척 자세와 발사 시점(0.14초), 회복 시간(0.5초)을 공유한다. 발사 뒤에는 빈손으로 회복하고 식칼이 다시 나타난다. 이동은 발사 직후 가능하며, 회복 중에는 투척 방향을 유지한다.
- 현재 게임은 `assets/cartoon/`의 카툰 캐릭터와 초상화를 사용한다. 모든 동작은 같은 `parts-source.png`의 몸·팔·다리 조각으로 만들어 동작 전환 시 그림체와 실루엣을 유지한다. 달리기는 30프레임을 60fps로 재생하며, 발의 이동과 들어 올리기를 1/4주기 어긋나게 해 번갈아 딛는다. 식칼을 든 팔은 빈손보다 작게 흔들고 투척 팔의 과도한 회전을 제한한다. 대기는 작은 호흡과 손 움직임을 2초 주기로 재생한다. 4개 방향을 반전·공유해 8방향에 대응하며, 방향 경계의 작은 흔들림을 억제하고 같은 동작에서 방향만 바뀌면 프레임과 경과 시간을 유지한다. 달리기 박자는 기본 이동 속도와 유체화·둔화 효과를 따르며, 충돌이나 목적지 직전의 짧은 이동 때문에 박자가 급변하지 않는다. 화면 갱신은 브라우저의 주기를 따른다. 이전 생성 달리기 스트립은 참고용으로 보존되어 있으며 현재 재생에는 사용하지 않는다.
- `npm run bake:cartoon`으로 아틀라스를 재생성하고, `npm run check:cartoon`으로 게임 실행·방향 전환·호흡·발 움직임·투척을 확인한다. `npm run preview:cartoon`은 **최종 아틀라스**에서 접촉 시트와 미리보기 프레임을 만든다. Pillow가 있는 Python으로 `tools/render-motion-gif.py`를 실행하면 `output/animation/`에 GIF를 저장한다. `http://localhost:5173/tools/animation-preview.html`에서 동작별 미리보기를 확인할 수 있다.
- 맵은 `assets/cartoon/arena.png`를 사용한다. 캐릭터와 같은 굵은 외곽선·단순한 명암의 둥근 바위, 보라색 수정, 잔잔한 카툰 물결로 구성한다. `npm run bake:arena`로 맵 이미지만 재생성한다.
- `assets/mundo.glb` — 원본 모델
- `tools/bake.*` — headless Chrome + Three.js로 GLB를 8방향 스프라이트 아틀라스(`assets/sprites/`)와 아레나 배경(`assets/arena.png`)으로 굽는다
  - `npm run bake` 전체 재생성 / `node tools/bake.mjs arena` 배경만 / `node tools/bake.mjs preview out.png "Clip,Clip@0-1"` 확인용 시트
- `src/config.js` — 투영 각도·해상도·애니메이션 목록 (게임과 베이크가 공유)
- `src/rules.js` — 밸런스 수치
- `src/sim.js` — 게임 계산 (이동 제한·투척·점멸·유체화·피격·사망·라운드 판정). Phaser·DOM 없이 브라우저 봇전과 서버가 함께 쓴다. 화면 효과는 `feed` 이벤트로만 알린다
- `src/main.js` — Phaser 씬. 씬이 sim 의 world 역할을 하며 이벤트를 받아 효과음·파티클을 그린다. 봇전은 로컬 계산, 대인전은 예측·보정·보간 (월드는 지면 좌표 x,z로 계산, 화면 y로 깊이 정렬)
- `src/online.js` — 게임 서버 연결·재접속·서버 시계 맞추기·대기실 화면
- `src/net-protocol.js` — 서버·브라우저 공용 상수와 스냅샷 압축 형식
- `server/index.mjs`, `server/room.mjs` — 1대1 게임 서버 (방, 준비, 카운트다운, 60Hz 판정, 재접속 대기, 재대결)
- `src/bot.js` — 봇 AI (회피, 예측 사격, 점멸 회피)
- `src/hud.js` — 롤 스타일 DOM HUD
- 검사: `npm run check:sim` (Node 단독 판정), `npm run check:online` (로컬 서버 + 브라우저 두 개로 콜로세움/기본 맵의 실제 클릭 좌표·외곽 이동 제한·점멸·유체화 동기화·봇전 축소 초기화·방 링크·준비·적중·따봉·KO 보상·재대결·새로고침 후 선택 맵 유지·상대 이탈 15초 안내). `ONLINE_MAPS=classic,colosseum npm run check:online`으로 진영을 바꾸고, `ONLINE_MAPS=colosseum,colosseum npm run check:online`으로 양쪽 콜로세움을 검사한다. 그 밖의 `tools/check-*.mjs`는 봇전 회귀 검사
